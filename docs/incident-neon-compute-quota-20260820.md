# 故障：Neon 计算配额耗尽导致全站 DB 路径 500（2026-08-20）

## 现象与发现路径

从「多页对比报告接口 500」一路查到数据库。**排查路径值得记下来，因为表象离根因很远**：

```
自检器 API 500（响应体为空）
  → 换 example.com 仍 500 ⇒ 不是目标站问题，是工具本身
  → vercel logs ⇒ 报错不是 Vercel 的，是 pg 抛的 code 53000
  → Neon API ⇒ 项目 zonit 配额耗尽，quota_reset_at = 2026-09-01
```

⚠️ **教训：`500` + 空响应体时，先看运行时日志再猜。** 我最初以为是抓取超时
（因为该接口 `maxDuration = 300`），但它 5 秒就返回了——**失败太快本身就是线索**。

## 影响面

| | 状态 | 原因 |
|---|---|---|
| 营销站静态页（首页 / 模板页） | ✅ 正常 | SSG，不查库 |
| 已发布的租户落地页 | ❌ 500 | `/p/[slug]` 每次渲染都查库 |
| 留资落库 | ❌ | 写库 |
| 邮箱验证码登录 / 后台 | ❌ | 查库 |
| 自检器与对比报告 | ❌ | 报告落库 |

**客户侧的在跑落地页与线索接收都在故障中**，不只是内部工具。

## 根因：不是配置项，是架构

**Neon 的免费额度建立在「计算会自动挂起」这个前提上**（默认空闲 300 秒后挂起）。
本项目同时满足了三个条件，把这个前提打掉了：

1. **`app/p/[slug]/page.tsx` 完全没有缓存**——没有 `revalidate`、没有 `use cache`、
   没有 `unstable_cache`，且调用 `headers()` 读租户域名，**强制每次请求都动态渲染**。
2. **每次渲染要查好几次库**：`getPublishedBySlug` + `getUserPlan`（`resolveCompanyInfo`
   不查库）。
3. **有一个每 60 秒一次的固定探测打在 `zapbridge.xyz/`**（100 条日志里 76 条是它，
   时间戳恒定落在每分钟的 `:43` 秒，每次 1–2 个请求）。

于是：**每分钟至少一次 DB 查询 → 空闲计时器永远归零 → 计算 24×7 不挂起。**

按最小规格 0.25 CU 计算，730 小时/月 ≈ 182 CU-小时，**光是空转就吃掉了几乎全部免费额度，
零余量**；任何一次自动伸缩到 2 CU 都会直接击穿。

⚠️ **连接池是干净的**，不是泄漏：`lib/db.ts` 的 `idleTimeoutMillis: 10_000`
比服务端更早回收，之前那轮 pg 坑已经修好了。**这次别再往连接池上找。**

## 为什么之前没暴露

`zapbridge.xyz` 是更名后**刻意保留的遗留根域**（PR #187，为解析与抢注防护）。
保留域名本身没错，**错在保留的域名指向了一个「每次访问都查库」的动态页**——
一个没人真正在用的遗留域，成了最大的计算消耗源。

## 修复方向（按优先级）

### 1. 立刻止血（免费，不改代码）

查出那个每 60 秒探测的来源并停掉，或让它改探静态页。若是自己配的 uptime 监控，
把目标从 `zapbridge.xyz/` 换成 `urgizat.com/`（SSG，不查库）即可。

⚠️ 但**这只是止血**：只要有真实访客持续访问已发布落地页，同样会把计算钉住。

### 2. 结构性修复：给 `/p/[slug]` 加缓存

已发布落地页读的是 `published_data`，**在下次发布前是不变的**——
这是最适合缓存的一类数据，现在却是全站唯一不缓存的热路径。

⚠️ 难点：该页用 `headers()` 取租户域名，直接整页 ISR 会丢掉按域名分流的逻辑。
正确做法是**缓存数据层而不是整页**（`unstable_cache` / `use cache` 包住
`getPublishedBySlug` 与 `getUserPlan`，按 slug 做 key），发布时按 tag 失效。
参见 `node_modules/next/dist/docs/` 里当前版本的 Cache Components 章节，
**别照搬旧版 API**。

### 3. 遗留根域不该走动态渲染

`zapbridge.xyz` / `zapbridge.site` 这类只为防抢注保留的根，应该在中间件里
直接静态 301 到 `urgizat.com`，**根本不进 `/p/[slug]`**。

### 4. 付费（如需立即恢复）

配额要到 2026-09-01 才重置。等 12 天期间客户落地页与线索持续掉，
若不可接受则需升级 Neon 套餐。**这是花钱的决定，由用户拍板。**

## ⚠️ 对冷启动计划的连带影响

A7 的测量方式是「每人一条唯一报告 URL，点击 = 读信证据」。**报告页现在 500。**
数据库恢复并验证报告页可用之前**不能发信**——否则收件人点开是错误页，
且零点击会被误读成「信没被读」，**又一次把测量本身搞坏**。
