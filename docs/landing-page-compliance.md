# 生成页的平台合规模型

本文覆盖生成落地页上「投放平台明文要求、且页面自身能满足」的那几项：政策可达、
经营主体、收集点告知、同意条、移动端可读。四家平台（Meta / Google / TikTok /
LinkedIn）各自的原文对比见 `docs/marketing/xiaohongshu/00-策略/平台系列.md`。

## 一条贯穿的原则

**我们只保证页面上有可核实的事实，不预测过不过审。** 这条同时约束三处实现：

| 位置 | 作用 | 是否阻断 |
| --- | --- | --- |
| `landing-editor/lib/publishIssues.ts` | 技术门槛：链接为空、缺必须模块 | 阻断发布 |
| `landing-editor/lib/complianceHints.ts` | 平台可能关注的缺项 | **不阻断** |
| `lib/tools/checks.ts`（自检器） | 对任意 URL 只报客观事实 | 不评分 |

把合规项塞进发布门槛等于我们替平台判定过审，做不到也不该做；一句不说，客户就要
靠被拒三次才知道页脚缺了什么。故第二档存在，且视觉上刻意与「校验未通过」区分。

## 政策子页（`/privacy`、`/terms`）

页脚的政策**段落**留在落地页上（医疗、法律模板的免责声明必须可见），同时挂出真实
链接 —— 平台会点开它，而页脚纯文本不构成「可达」。历史教训：我们自己的自检器
`findPolicyLinks` 只认 `<a>`，改造前实测判自己的生成页 `privacy_missing` +
`terms_missing`（回归测试见 `landing-renderer/compliance.test.ts`）。

- 地址规则单一真源：`lib/landing-pages/policy-paths.ts`（生成与反解互逆，有测试锁）。
- 落地页发布在 `/` → `/privacy`；发布在 `/invisalign` → `/invisalign/privacy`。
- 中间件 `lib/proxy/tenant-proxy.ts`：**先试精确路由绑定**，未命中再按政策子页兜底。
  客户真把某张页发布在 `/privacy` 时，那张页优先。
- 政策页恒 `noindex`：正文与页脚同源，被索引就是跨租户的薄重复内容。
- 三处预览同构（公开页 / 分享预览 / 编辑器预览），因为客户第一次检查页脚是在预览里，
  点开 404 会被读成「功能没做」。

## 经营主体（`company_profiles`）

TikTok 对电商与金融类页面明确要求页脚展示公司信息与执照；Meta / LinkedIn 也核对
页面身份是否真实。平台无从代填，编造更糟，故只提供录入位置 + 非阻断提示。

- **账号级实体，可建多份**（不同法律实体 / 不同市场），在编辑器页脚面板逐页选用。
- 落地页存**引用**（`footer.companyProfileId`）而非文案快照：改一次主体信息，所有
  引用它的已发布页立即跟上；快照会当场分裂成 N 份互相矛盾的主体信息。
- 渲染端不碰库：路由用 `lib/company-profiles/resolve.ts` 解析后把成文的一行传进去。
- 解析失败（未选 / 已删 / 跨账号 id）一律不展示，**不回退到默认主体** —— 页面上出现
  客户没选过的法律实体比缺失更糟。
- 删除前查引用（`countPagesUsingProfile`），仍被引用则 409：那些页可能正在投放。
- 页脚那一行的成文规则只有一份：`lib/company-profiles/format.ts`，服务端与编辑器
  实时预览共用。

## 收集点告知

表单旁的 “By submitting this form you agree to our Privacy Policy.” 只在拿得到政策
链接时渲染 —— 没有链接的「见隐私政策」是空口承诺，比不写更糟。

## 同意条

- 缺省文案为**英文**：生成页面向海外访客，同意的前提是访客读得懂。曾硬编码中文，
  欧盟访客拿到一条看不懂的中文同意条。需要其它语言由 `tracking.consent.text` 覆盖。
- 只在**真的有东西要征求同意**时出现：有第三方 pixel，或访客属欧盟/EEA（第一方
  beacon 对这些访客也受门控）。判据在 `lib/tracking/geo.ts` 的 `needsConsentBar`。

## 移动端可读

自检器只检查 viewport 声明（存在 / 是否禁止缩放）：这是静态 HTML 里唯一客观可核实
的移动端事实。字号要靠渲染后的计算样式才算得准，静态猜字号只会造出一条不可靠的
检查项。TikTok 要求移动端不放大就能读，Google 把移动端可用性算进着陆页体验。

## 域名一致性（页面之外）

Google 与 LinkedIn 要求广告展示 URL 的域名与实际落地域名一致。用平台子域发布本身
没问题，但客户容易在广告里把展示 URL 填成自己的品牌域 —— 那是直接违规，且被拒理由
通常看不出是这个原因。发布弹窗在选中平台子域时给出提示。

## 已知不做

- 不做「合规评分」「过审概率」：见上文原则。
- 不在生成页引入任何交易语义（见 `CLAUDE.md` 硬规则），故 TikTok 对电商类页面的
  「本地货币价格」等要求不在本产品范围内 —— 生成页不是交易页。
